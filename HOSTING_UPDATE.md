# Готовая production-сборка HeroList

## Основной принцип

`main` всегда содержит уже скомпилированную папку `dist/`.

Исходники и готовая сборка публикуются вместе. GitHub Actions больше не
переписывает `dist`: workflow только независимо пересобирает проект и
проверяет, что закоммиченный `dist` соответствует исходникам.

Для выпуска обновления:

1. внести изменения в исходники;
2. локально выполнить `npm ci` и `npm run build`;
3. выполнить `python3 scripts/sanitize-committed-dist.py`;
4. выполнить `python3 scripts/write-build-info.py`;
5. закоммитить исходники и готовый `dist/`;
6. дождаться зелёного Verify HeroList.

## Запуск готовой сборки

`vinext`, `react` и `react-dom` находятся в обычных `dependencies`
`package.json`. Для запуска готовой production-сборки не нужны Vite,
TypeScript и другие dev-пакеты.

Достаточно:

```bash
npm ci --omit=dev --ignore-scripts
npm start
```

`npm start` запускает `deployment/start-frontend.mjs`, который использует
готовый `dist/`.

Для обычного обновления production-хоста достаточно подтянуть актуальный `main`.
Пересобирать frontend на хосте не нужно: папка `dist/` уже готова к запуску.
Если изменился `package-lock.json`, достаточно повторить `npm ci --omit=dev --ignore-scripts`.

Если нужен только GitHub Pages production, он публикуется workflow
`Publish GitHub Pages` после успешной проверки `main`.

## Что не делать

Не выполнять на машине, где нужна только готовая версия:

```bash
npm run build
vite build
vinext build
```

Не редактировать содержимое `dist/` вручную. Оно должно получаться только из
локальной сборки соответствующих исходников.

## Проверка соответствия

`dist/BUILD_INFO.json` содержит SHA исходного коммита и время локальной
сборки. CI нормализует ожидаемую случайность Vinext и сравнивает готовый
`dist` с независимой пересборкой.
После локальной сборки готовый `dist/` должен быть закоммичен в ту же ветку до её слияния в `main`; CI после этого только пересобирает и сравнивает результат.
